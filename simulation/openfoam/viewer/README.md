# MCC Simulation Viewer

A dependency-free, static viewer for the microfluidic T-junction digital twin.
Three tabs:

- **2D T-junction** — the `alpha.water` field played back over a drip cycle
  (scrub, play/pause, colormap, interface highlight). Real interFoam output,
  resampled to a regular grid.
- **3D droplet** — the rendered 3D water isosurface (necking + pinch-off). A
  pre-rendered loop today; wired to accept an interactive isosurface export.
- **Metrics** — droplet length `L/w` and formation frequency vs flow-rate ratio
  `q`, grouped by capillary number `Ca`, from a swept dataset.

No build step, no backend, no framework. Just static files: `index.html`,
`styles.css`, `app.js`, and the generated data under `data/`.

## Run it

Because the data loads via `<script>` tags, it works by opening `index.html`
directly. To also load the 3D GIF (a relative path into `../results/`), serve
from the `simulation/openfoam/` directory:

```bash
cd simulation/openfoam
python3 -m http.server 8000
# open http://localhost:8000/viewer/
```

## Regenerating the data

The committed `data/*.js` are generated by [`export_web.py`](export_web.py),
which needs a Python with `vtk`, `numpy`, and `scipy`.

**2D field frames** — from any 2D case that has been converted to legacy VTK:

```bash
# run a 2D case (interFoam), then convert:
#   blockMesh && setFields && interFoam && foamToVTK -legacy
python3 export_web.py twod /path/to/case --nx 200 --out data/twod_frames.js
```

The mesh is static, so the grid→cell resampling is built once and reused per
frame; cells outside the channel get a sentinel value so the walls draw. Keep
`--nx` modest (≈200) — every frame is embedded in the `.js`, so resolution ×
frame-count is the file size.

**Metric charts** — from a sweep results CSV (velocity-driven, `status == ok`
rows are used):

```bash
python3 export_web.py metrics ../results/sweep_2026-07/sweep_results.csv --out data/metrics.js
```

## Wiring up interactive 3D (later)

The 3D tab currently shows `../results/mill3d800_2026-08/droplet_3d_800um.gif`.
The 3D field data (VTK) is multi-gigabyte and lives outside the repo (see
`../nightly/`), so an interactive isosurface isn't committed. The intended path
is to extend `export_web.py` with a `threed` command that decimates the
`alpha.water = 0.5` isosurface per timestep to glTF, and add a small WebGL
canvas to the 3D tab. Not built yet — the hook and note are in place.

## Notes

- This viewer replaces the old FastAPI/React `webapp/`, which predated the sim
  rework and drove a now-defunct toolchain. It is a *viewer*, not a sim
  launcher — runs happen via the case `Allrun`s and `../nightly/`.
